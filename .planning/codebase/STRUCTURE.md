## Directory Purposes

**`lib/`:**
- Purpose: All application Dart source code
- Contains: Entry point, screens, widgets, providers, services, models
- Key files: `lib/main.dart`

**`lib/models/` (planned):**
- Purpose: Data transfer objects matching backend JSON schema
- Contains: `User`, `Dish`, `Review`, `Canteen`, `Window`, `Wish` classes
- Pattern: Each file exports one class with `fromJson` factory and `toJson` method

**`lib/services/` (planned):**
- Purpose: All HTTP communication with the FastAPI backend
- Contains: `ApiService` class wrapping every `/api/v1/` endpoint
- Pattern: Single class, methods grouped by resource (auth, canteens, dishes, reviews, recommend)

**`lib/providers/` (planned):**
- Purpose: Observable state containers for the widget tree
- Contains: `UserProvider` (auth + preferences), `DishProvider` (dish/canteen data)
- Pattern: `ChangeNotifier` subclasses registered at app root via `MultiProvider`

**`lib/screens/` (planned):**
- Purpose: One file per navigable page
- Contains: Full-page `StatefulWidget` or `StatelessWidget` classes
- Pattern: Screen reads from Provider via `context.watch`, triggers actions via `context.read`

**`lib/widgets/` (planned):**
- Purpose: Reusable UI components shared across screens
- Contains: Rating star widget, review card, dish card, badge widget
- Pattern: Stateless widgets receiving all data via constructor parameters

**`test/`:**
- Purpose: Automated tests
- Contains: `widget_test.dart` (default smoke test)
- Key files: `test/widget_test.dart`

**`android/`:**
- Purpose: Android platform embedding
- Contains: `MainActivity.kt`, Android manifest, app icons, Gradle build files
- Key files: `android/app/src/main/kotlin/com/example/what_to_eat_today/MainActivity.kt`

**`ios/`:**
- Purpose: iOS platform embedding
- Contains: Xcode project, Runner app delegate, app icons, launch images
- Key files: `ios/Runner/AppDelegate.swift` (generated by Flutter)

**`.planning/`:**
- Purpose: GSD planning and codebase analysis documents
- Generated: No
- Committed: Yes

## Naming Conventions

**Files:**
- Dart source files: `snake_case.dart` (e.g., `dish_detail_screen.dart`, `api_service.dart`)
- Test files: `snake_case_test.dart` (e.g., `widget_test.dart`)
- Screen files: suffix `_screen.dart`
- Provider files: suffix `_provider.dart`
- Service files: suffix `_service.dart`
- Model files: named after the entity (e.g., `dish.dart`, `review.dart`)

**Directories:**
- All lowercase, plural nouns: `screens/`, `widgets/`, `models/`, `services/`, `providers/`

**Classes:**
- `PascalCase` for all Dart classes (e.g., `MyApp`, `DishDetailScreen`, `UserProvider`)
- `_PascalCase` for private State classes (e.g., `_MyHomePageState`)

**Variables and methods:**
- `camelCase` for all variables, parameters, and methods
- `_camelCase` for private fields and methods

## Where to Add New Code

**New screen/page:**
- Implementation: `lib/screens/<feature>_screen.dart`
- Tests: `test/screens/<feature>_screen_test.dart`

**New reusable widget:**
- Implementation: `lib/widgets/<widget_name>.dart`
- Tests: `test/widgets/<widget_name>_test.dart`

**New data model:**
- Implementation: `lib/models/<entity>.dart`
- Include `fromJson(Map<String, dynamic> json)` factory and `toJson()` method

**New API endpoint wrapper:**
- Add method to `lib/services/api_service.dart`
- Group methods by resource (auth, canteens, dishes, reviews, recommend)

**New state container:**
- Implementation: `lib/providers/<feature>_provider.dart`
- Extend `ChangeNotifier`; register in `MultiProvider` in `lib/main.dart`

**New utility/helper:**
- Implementation: `lib/utils/<helper_name>.dart` (create `utils/` directory when needed)
